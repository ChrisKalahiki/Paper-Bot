# Domain docs

## Layout and reading rules

This is a single-context repository.

Before exploring, read root `GLOSSARY.md` and any ADRs in `docs/adr/`
relevant to the work.

If either is absent, proceed silently. Domain documentation is created
as terminology or decisions are resolved, rather than scaffolded upfront.

## Vocabulary

Use the glossary's terms in code, tests, issues and proposals.
If a needed concept is missing, reconsider the terminology or flag the
gap for domain-modeling.

## ADR conflicts

Surface conflicts with existing ADRs explicitly, citing the ADR and
explaining why the decision should be reconsidered.
